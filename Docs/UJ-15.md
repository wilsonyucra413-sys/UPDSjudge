# UJ-15 - Recepción del veredicto de un envío

## Descripción

Como usuario, quiero recibir el veredicto de mi envío en el menor tiempo posible para conocer inmediatamente si mi solución fue aceptada o si contiene errores.

Esta funcionalidad permite que el sistema evalúe automáticamente el código enviado y devuelva el resultado final del procesamiento, junto con los datos del envío registrado.

---

## Endpoint de evaluación del envío

**POST** `/api/envios/`

### Objetivo funcional

Este endpoint recibe el código fuente del usuario, el concurso, el inciso del problema y el lenguaje seleccionado.
Luego ejecuta la evaluación automática y devuelve el veredicto generado para ese envío.

---

## Validaciones realizadas en el envío

### 1. Validación del código fuente

El código fuente es obligatorio.

**Si está vacío:**

```json id="q8m1fa"
{
  "mensaje": "El código fuente es obligatorio."
}
```

---

### 2. Validación del código del concurso

El código del concurso es obligatorio.

**Si está vacío:**

```json id="m4q7nz"
{
  "mensaje": "El código del concurso es obligatorio."
}
```

---

### 3. Existencia del concurso

Se busca un concurso activo con el código enviado.

**Si no existe o fue eliminado:**

```json id="b2r9kp"
{
  "mensaje": "El concurso no existe o fue eliminado."
}
```

---

### 4. Existencia del problema

Se verifica que el inciso indicado pertenezca al concurso y que el problema esté activo.

**Si no existe:**

```json id="k7v3dx"
{
  "mensaje": "No existe el problema con inciso 'B' en este concurso."
}
```

---

### 5. Validación del estado temporal del concurso

El sistema calcula si el concurso está:

* **Próximo**
* **Activo**
* **Finalizado**

#### Si el concurso todavía no inicia:

```json id="x3c8rt"
{
  "mensaje": "El concurso todavía no ha iniciado."
}
```

---

### 6. Validación de participación del usuario

Si el usuario no está inscrito y no es el creador del concurso, se aplican restricciones:

* no puede enviar soluciones mientras el concurso está en curso
* si el concurso ya finalizó, solo puede enviar en modo upsolving

#### Si intenta enviar sin estar inscrito durante el concurso:

```json id="d9w2ap"
{
  "mensaje": "Debes estar inscrito para enviar soluciones mientras el concurso está en curso."
}
```

---

### 7. Validación de concurso privado en upsolving

Si el concurso es privado y el usuario no está inscrito, debe ingresar la contraseña para hacer upsolving.

#### Si no envía contraseña:

```json id="n6t5hy"
{
  "mensaje": "Este concurso es privado, ingresa la contraseña para hacer upsolving."
}
```

#### Si la contraseña es incorrecta:

```json id="p1z8ul"
{
  "mensaje": "Contraseña incorrecta."
}
```

---

## Proceso de evaluación

Una vez superadas las validaciones, el sistema:

1. obtiene el problema asociado
2. toma el lenguaje seleccionado
3. ejecuta el código contra los casos de prueba
4. determina el veredicto final
5. guarda el envío
6. devuelve el resultado al usuario

---

## Veredictos posibles

El sistema puede devolver los siguientes veredictos:

* **Accepted**
* **Wrong Answer**
* **Time Limit Exceeded**
* **Memory Limit Exceeded**
* **Compilation Error**
* **Runtime Error**

### Equivalencias comunes

| Código | Veredicto             |
| ------ | --------------------- |
| `AC`   | Accepted              |
| `WA`   | Wrong Answer          |
| `TLE`  | Time Limit Exceeded   |
| `MLE`  | Memory Limit Exceeded |
| `CE`   | Compilation Error     |
| `RE`   | Runtime Error         |

---

## Respuesta del envío

La respuesta del `POST` devuelve el resultado evaluado y los datos básicos del envío.

### Ejemplo de respuesta exitosa

```json id="s4v0np"
{
  "idEnvio": 123,
  "veredicto": "Accepted",
  "tiempo": 0.12,
  "memoria": 1536,
  "upsolving": false,
  "detalle": null
}
```

---

## Endpoint de consulta de envíos por concurso

**GET** `/api/envios/concurso/{concursoCodigo}`

### Objetivo funcional

Este endpoint permite consultar los envíos realizados por el usuario dentro de un concurso específico, mostrando el veredicto obtenido en cada uno.

También permite filtrar por:

* resultado
* inciso del problema
* paginación

---

## Parámetros de consulta

### `resultado`

Permite filtrar por veredicto.

Valores aceptados:

* `AC`
* `WA`
* `TLE`
* `MLE`
* `CE`
* `RE`

### `inciso`

Permite filtrar por el inciso del problema.

### `pagina`

Número de página.

* mínimo: `1`
* valor por defecto: `1`

### `tamanoPagina`

Cantidad de resultados por página.

* mínimo: `1`
* máximo: `50`
* valor por defecto: `20`

---

## Validaciones realizadas en la consulta

### 1. Validación del concurso

El código del concurso es obligatorio y debe corresponder a un concurso activo.

**Si está vacío:**

```json id="u9h3rc"
{
  "mensaje": "El código del concurso es obligatorio"
}
```

**Si no existe o no está activo:**

```json id="e5k0vm"
{
  "mensaje": "Concurso no encontrado o no está activo"
}
```

---

### 2. Validación de paginación

Si `pagina` es menor que `1`, se ajusta automáticamente a `1`.

Si `tamanoPagina` es menor que `1` o mayor que `50`, se ajusta automáticamente a `20`.

---

### 3. Validación del filtro por veredicto

Si se envía `resultado`, se traduce al veredicto interno correspondiente.

Si el valor no coincide con uno conocido, se usa tal como llega para la búsqueda.

---

### 4. Validación del inciso

Si se envía `inciso`, se toma el primer carácter y se normaliza a mayúscula para filtrar los envíos.

---

## Datos devueltos por cada envío

Cada elemento del listado incluye:

* `idEnvio`
* `concursoCodigo`
* `problemaTitulo`
* `inciso`
* `lenguaje`
* `veredicto`
* `consumoTiempo`
* `consumoMemoria`
* `fechaEnvio`

---

## Respuesta exitosa de la consulta

### HTTP 200

```json id="c8p2vn"
{
  "total": 3,
  "pagina": 1,
  "tamanoPagina": 20,
  "datos": [
    {
      "idEnvio": 123,
      "concursoCodigo": "upds-div4-001",
      "problemaTitulo": "Suma",
      "inciso": "A",
      "lenguaje": "C++ (GCC 9.2.0)",
      "veredicto": "Accepted",
      "consumoTiempo": 0.12,
      "consumoMemoria": 1536,
      "fechaEnvio": "2026-07-26T18:20:00Z"
    }
  ]
}
```

---

## Reglas de negocio

* El código fuente es obligatorio.
* El concurso debe existir y estar activo.
* El problema debe pertenecer al concurso.
* El concurso no puede estar en estado `Próximo` al enviar soluciones.
* El usuario debe estar inscrito para enviar durante el concurso.
* En concursos privados, el upsolving requiere contraseña.
* El veredicto se devuelve inmediatamente después de la evaluación.
* Los envíos del usuario pueden consultarse posteriormente por concurso, resultado o inciso.

---

## Resumen funcional

La UJ-15 permite que el usuario reciba de forma inmediata el veredicto de su envío tras la evaluación automática y, además, consulte sus envíos dentro de un concurso filtrándolos por veredicto o por inciso.
