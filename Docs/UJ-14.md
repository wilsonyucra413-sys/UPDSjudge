# UJ-14 - Envío y evaluación de código fuente

## Descripción

Como usuario, quiero seleccionar un lenguaje de programación como **C++**, **Python** o **C#** y subir mi código para que sea evaluado automáticamente.

Esta funcionalidad permite registrar un envío asociado a un problema de un concurso y obtener un veredicto según el resultado de la evaluación.

---

## Endpoint

**POST** `/api/envios/`

### Ejemplo de solicitud

```json
{
  "codigoConcurso": "upds-div4-012",
  "incisoProblema": "b",
  "idLenguaje": 1,
  "codigoFuente": "#include <iostream>\nusing namespace std;\n\nint main() {\n    int a, b;\n    cin >> a >> b;\n    cout << a - b << endl;\n    return 0;\n}"
}
```

---

## Objetivo funcional

El endpoint recibe:

* el código del concurso
* el inciso del problema
* el lenguaje seleccionado
* el código fuente del usuario

Luego valida la solicitud, ejecuta la evaluación sobre los casos de prueba del problema y guarda el envío con su resultado.

---

## Validaciones realizadas

### 1. Validación del código fuente

El código fuente es obligatorio.

**Si está vacío:**

```json
{
  "mensaje": "El código fuente es obligatorio."
}
```

---

### 2. Validación del código del concurso

El código del concurso es obligatorio.

**Si está vacío:**

```json
{
  "mensaje": "El código del concurso es obligatorio."
}
```

---

### 3. Validación de existencia del concurso

Se busca un concurso activo con el código enviado.

**Si no existe o fue eliminado:**

```json
{
  "mensaje": "El concurso no existe o fue eliminado."
}
```

---

### 4. Validación del problema dentro del concurso

Se verifica que exista un problema activo con el inciso indicado dentro del concurso.

**Si no existe:**

```json
{
  "mensaje": "No existe el problema con inciso 'B' en este concurso."
}
```

---

### 5. Validación del estado temporal del concurso

Se calcula el estado actual del concurso:

* **Próximo**
* **Activo**
* **Finalizado**

#### Si el concurso todavía no ha iniciado:

```json
{
  "mensaje": "El concurso todavía no ha iniciado."
}
```

---

### 6. Validación de participación del usuario

Si el usuario no está inscrito y no es el creador del concurso, se aplican reglas adicionales:

* mientras el concurso está en curso, no puede enviar soluciones
* si el concurso ya finalizó, solo puede hacer **upsolving**

#### Si intenta enviar durante el concurso sin estar inscrito:

```json
{
  "mensaje": "Debes estar inscrito para enviar soluciones mientras el concurso está en curso."
}
```

---

### 7. Validación de concurso privado en upsolving

Si el concurso es privado y el usuario no está inscrito, debe ingresar la contraseña para enviar soluciones después de finalizado el concurso.

#### Si no envía contraseña:

```json
{
  "mensaje": "Este concurso es privado, ingresa la contraseña para hacer upsolving."
}
```

#### Si la contraseña es incorrecta:

```json
{
  "mensaje": "Contraseña incorrecta."
}
```

---

### 8. Validación del lenguaje

El lenguaje seleccionado debe existir y estar activo.

**Si no está soportado:**

```json
{
  "mensaje": "El lenguaje indicado no está soportado."
}
```

---

### 9. Validación de casos de prueba

El problema debe tener casos de prueba configurados para poder ser evaluado.

**Si no tiene casos de prueba:**

```json
{
  "mensaje": "Este problema no tiene casos de prueba configurados."
}
```

---

## Proceso de evaluación

Si todas las validaciones son correctas, el sistema:

1. toma el problema asociado al inciso
2. obtiene los casos de prueba activos
3. ejecuta el código con el lenguaje seleccionado
4. compara la salida obtenida con la salida esperada
5. calcula el veredicto final
6. guarda el envío en la base de datos

---

## Lenguajes permitidos

La solución está pensada para trabajar con los lenguajes registrados en el sistema, incluyendo:

* C++
* Python
* C#

---

## Veredictos posibles

El sistema puede devolver, entre otros, los siguientes resultados:

* **Accepted**
* **Wrong Answer**
* **Time Limit Exceeded**
* **Compilation Error**
* **Runtime Error**
* **Memory Limit Exceeded**

---

## Información registrada del envío

Cuando el envío se guarda correctamente, se almacena:

* código fuente
* resultado del envío
* tiempo de ejecución
* memoria utilizada
* token de evaluación
* tipo de envío: normal o upsolving
* fecha del envío
* usuario
* problema
* lenguaje

---

## Respuesta exitosa

### HTTP 200

La respuesta incluye el resultado de la evaluación.

```json
{
  "idEnvio": 123,
  "veredicto": "Accepted",
  "tiempo": 0.12,
  "memoria": 1536,
  "upsolving": false,
  "detalle": null
}
```
## Configuración inicial de lenguajes

El sistema registra previamente los lenguajes disponibles para la evaluación de envíos.
Estos lenguajes quedan cargados en la base de datos como datos iniciales y son los que el usuario puede seleccionar al momento de enviar su solución.

### Lenguajes disponibles

```csharp
modelBuilder.Entity<Lenguaje>().HasData(
    new Lenguaje { idLenguaje = 1, idJudge0 = 54, nombre = "C++ (GCC 9.2.0)", extension = "cpp", estado = "Activo" },
    new Lenguaje { idLenguaje = 2, idJudge0 = 71, nombre = "Python (3.8.1)", extension = "py", estado = "Activo" },
    new Lenguaje { idLenguaje = 3, idJudge0 = 51, nombre = "C# (Mono 6.6.0.161)", extension = "cs", estado = "Activo" }
);
```

### Reglas de negocio asociadas

* Solo se permiten lenguajes previamente registrados en el sistema.
* Cada lenguaje debe estar activo para poder usarse en un envío.
* Cada lenguaje tiene asociado su identificador correspondiente en Judge0.
* El lenguaje seleccionado determina cómo será ejecutado el código fuente enviado por el usuario.
* La extensión del lenguaje sirve como referencia para la presentación y manejo del código en el frontend.

### Lenguajes soportados

| Id | Lenguaje            | Extensión | Judge0 |
| -- | ------------------- | --------- | ------ |
| 1  | C++ (GCC 9.2.0)     | `cpp`     | 54     |
| 2  | Python (3.8.1)      | `py`      | 71     |
| 3  | C# (Mono 6.6.0.161) | `cs`      | 51     |

---

## Respuestas de error

### HTTP 400

Se devuelve cuando:

* falta el código fuente
* falta el código del concurso
* el concurso todavía no ha iniciado
* el usuario no puede enviar en ese momento
* falta la contraseña para upsolving en concursos privados
* el lenguaje no está soportado
* el problema no tiene casos de prueba
* hay cualquier validación de negocio fallida

### HTTP 401

Se devuelve cuando la contraseña del concurso privado es incorrecta.

### HTTP 404

Se devuelve cuando el concurso o el problema no existen.

### HTTP 503

Se devuelve cuando el motor de ejecución no está disponible temporalmente.

---

## Reglas de negocio

* El código fuente es obligatorio.
* El concurso debe existir y estar activo.
* El problema debe pertenecer al concurso.
* No se permiten envíos mientras el concurso está en curso si el usuario no está inscrito.
* Después de finalizado el concurso, los usuarios no inscritos pueden hacer upsolving.
* En concursos privados, el upsolving requiere contraseña.
* El lenguaje seleccionado debe estar registrado y activo.
* El envío se evalúa contra los casos de prueba del problema.
* El resultado final se guarda en la base de datos.

---

## Resumen funcional

La UJ-14 permite que el usuario seleccione un lenguaje, envíe su código y reciba una evaluación automática contra los casos de prueba del problema del concurso, registrando el resultado final del envío.
