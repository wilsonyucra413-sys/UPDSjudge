# UJ-13 - Visualización del dashboard del concurso

## Descripción

Como usuario dentro de un concurso, quiero ver la lista de incisos (`A`, `B`, `C`...) y un botón para abrir el PDF del set de problemas de Google Drive.

Esta funcionalidad permite consultar el tablero principal del concurso, mostrando sus problemas, su estado general, la cantidad de intentos realizados y el enlace al documento del set de problemas.

---

## Endpoint

**GET** `/api/Concursos/dashboard/{codigo}`

### Ejemplo

```http
http://localhost:5185/api/Concursos/dashboard/upds-div4-001
```

---

## Objetivo funcional

El endpoint devuelve la información necesaria para visualizar el dashboard de un concurso, incluyendo:

* código del concurso
* nombre
* estado temporal
* cantidad de participantes
* fecha de fin
* minutos de congelamiento
* enlace al set de problemas
* lista de problemas con inciso, título, tiempo, memoria, intentos y estado de resolución

---

## Validaciones realizadas

### 1. Validación del identificador del usuario

Se verifica que el token contenga el identificador del usuario autenticado.

**Si falla:**

```json id="yq7l2f"
{
  "mensaje": "Token inválido"
}
```

---

### 2. Validación del código del concurso

El código recibido se normaliza con trim y conversión a minúsculas.

Luego se verifica que no esté vacío.

**Si está vacío:**

```json id="g7n5b1"
{
  "mensaje": "El código del concurso es obligatorio."
}
```

---

### 3. Existencia del concurso

Se busca un concurso activo con el código enviado.

**Si no existe o fue eliminado:**

```json id="k3p8m4"
{
  "mensaje": "El concurso no existe o fue eliminado."
}
```

---

### 4. Validación del estado temporal del concurso

El sistema calcula el estado del concurso según la fecha actual:

* **Próximo**
* **Activo**
* **Finalizado**

---

### 5. Validación de acceso al dashboard

No se permite ver el dashboard si el concurso todavía está en estado **Próximo**, salvo que el usuario cumpla una condición de acceso válida.

El acceso se permite únicamente cuando:

* el concurso ya no está en estado `Próximo`, y
* el concurso no es privado, o
* el usuario ya está inscrito, o
* el usuario es el creador del concurso

**Si no puede verlo:**

```json id="3wq9rt"
{
  "mensaje": "Todavía no puedes ver el dashboard de este concurso."
}
```

---

## Datos que se consultan para el dashboard

Para construir la respuesta, el sistema obtiene:

* información general del concurso
* lista de problemas activos
* intentos del usuario sobre esos problemas
* estado de cada problema
* enlace al PDF del set de problemas

---

## Información incluida por cada problema

Cada problema del dashboard incluye:

* `inciso`
* `titulo`
* `tiempo`
* `memoria`
* `intentos`
* `estado`
* `resuelto`

---

## Cálculo del estado de cada problema

El sistema evalúa los envíos del usuario para cada problema.

### Casos posibles

#### Sin intentos

Si el usuario no ha enviado ninguna solución al problema:

```text id="b7k2sp"
Sin intentar
```

#### Con intentos

Si existen envíos, se toma el estado del envío más reciente.

#### Problema resuelto

Si alguno de los envíos del problema fue aceptado, el problema se marca como resuelto.

---

## Cálculo de métricas generales del dashboard

El endpoint también calcula:

* `problemasResueltos`
* `totalProblemas`
* `intentosTotales`
* `segundosRestantes`

### Segundos restantes

Solo se calculan si el concurso está en estado **Activo**.

Si el concurso ya finalizó o todavía no comenzó, este valor será `null`.

---

## Botón para abrir el set de problemas

El dashboard devuelve el campo:

```text id="v8c0hn"
urlSetProblemas
```

Este campo contiene el enlace al archivo PDF alojado en Google Drive o en el recurso definido por el concurso.

Ese enlace es el que debe usarse en el frontend para mostrar el botón de acceso al set de problemas.

---

## Reglas de negocio

* El concurso debe existir y estar activo como registro general.
* El código del concurso es obligatorio.
* El dashboard no puede verse si el concurso aún está en estado **Próximo**, salvo acceso permitido.
* Si el concurso es privado, solo puede visualizarse si el usuario está inscrito o es el creador.
* Se muestran únicamente los problemas activos.
* Se ordenan los problemas por inciso.
* Se calculan los intentos y el estado de cada problema usando los envíos del usuario.
* Se expone el enlace al set de problemas para que el frontend pueda abrirlo.

---

## Resumen funcional

La UJ-13 permite visualizar el dashboard del concurso con sus incisos, estado general, métricas de participación, intentos del usuario y el enlace al PDF del set de problemas, siempre que el usuario tenga acceso válido a ese concurso.
