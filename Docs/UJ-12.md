# UJ-12 - Inscripción a concurso privado mediante contraseña

## Descripción

Como usuario, quiero ingresar la contraseña de un concurso privado para poder participar oficialmente.

Esta funcionalidad permite que un usuario se inscriba a un concurso, validando primero si el concurso es privado y, en ese caso, verificando la contraseña ingresada.

---

## Endpoint

**POST** `/api/ParticipanteConcursos/unirse`

---

## Objetivo funcional

El endpoint permite registrar la participación de un usuario en un concurso existente, siempre que el concurso sea válido, no pertenezca al mismo usuario creador y cumpla las condiciones de acceso definidas por el sistema.

En concursos privados, la inscripción solo se permite si la contraseña proporcionada es correcta.

---

## Validaciones realizadas

### 1. Validación del identificador del usuario

El sistema verifica que el token contenga el identificador del usuario autenticado.

**Si falla:**

```json
{
  "mensaje": "Token inválido"
}
```

---

### 2. Validación del código del concurso

El código recibido se normaliza con `trim` y conversión a minúsculas.

Luego se verifica que no esté vacío.

**Si está vacío:**

```json
{
  "mensaje": "El código del concurso es obligatorio."
}
```

---

### 3. Existencia del concurso

Se busca un concurso activo con el código enviado.

**Si no existe o fue eliminado:**

```json
{
  "mensaje": "El concurso no existe o fue eliminado."
}
```

---

### 4. Validación de autoría

El creador del concurso no puede inscribirse a su propio concurso.

**Si el usuario es el creador:**

```json
{
  "mensaje": "No puedes inscribirte a un concurso que tú mismo creaste."
}
```

---

### 5. Validación del estado temporal del concurso

El sistema calcula el estado del concurso según la fecha actual:

* **Próximo**
* **Activo**
* **Finalizado**

Si el concurso está **Activo**, no se permiten inscripciones.

**Si está en curso:**

```json
{
  "mensaje": "Las inscripciones están cerradas mientras el concurso está en curso."
}
```

---

### 6. Validación de concurso privado

Si el concurso tiene contraseña, se considera privado.

En ese caso:

* la contraseña debe enviarse obligatoriamente
* la contraseña debe coincidir con la registrada

#### Si no se envía contraseña:

```json
{
  "mensaje": "Este concurso es privado, debes ingresar la contraseña."
}
```

#### Si la contraseña es incorrecta:

```json
{
  "mensaje": "Contraseña incorrecta."
}
```

---

### 7. Validación de inscripción previa

El sistema verifica si el usuario ya tiene una participación registrada en ese concurso.

#### Si ya está inscrito y activo:

```json
{
  "mensaje": "Ya estás inscrito en este concurso.",
  "codConcurso": "codigo-del-concurso"
}
```

---

### 8. Reactivación de una inscripción previa

Si el usuario ya existía como participante pero su estado no estaba activo, el sistema reactiva su participación.

Se actualiza:

* `estado = Activo`
* `fechaIngreso = fecha actual`

#### Resultado:

```json
{
  "mensaje": "Te has vuelto a inscribir al concurso.",
  "codConcurso": "codigo-del-concurso"
}
```

---

### 9. Inserción de nueva participación

Si no existe una participación previa, se crea un nuevo registro en la tabla de participantes del concurso.

#### Resultado exitoso:

```json
{
  "mensaje": "Te has inscrito al concurso exitosamente.",
  "codConcurso": "codigo-del-concurso"
}
```

---

### 10. Control de duplicados por base de datos

Si ocurre un conflicto al guardar la inscripción, el sistema captura el error y responde como si el usuario ya estuviera inscrito.

#### Resultado:

```json
{
  "mensaje": "Ya estás inscrito en este concurso.",
  "codConcurso": "codigo-del-concurso"
}
```

---

## Reglas de negocio

* Solo un usuario autenticado puede inscribirse.
* El código del concurso es obligatorio.
* El concurso debe existir y estar activo como registro general.
* El creador del concurso no puede participar en su propio concurso.
* Las inscripciones están cerradas mientras el concurso está en curso.
* Si el concurso es privado, la contraseña es obligatoria.
* La contraseña debe coincidir exactamente con la registrada.
* Si el usuario ya estaba inscrito, no se duplica la participación.
* Si tenía una participación previa desactivada, esta puede reactivarse.

---

## Respuestas posibles

| HTTP | Motivo                                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 200  | Inscripción exitosa, reinscripción o usuario ya inscrito.                                                                           |
| 400  | Código vacío, concurso inválido, creador intentando inscribirse, concurso en curso, contraseña faltante o inscripción no permitida. |
| 401  | Contraseña incorrecta o token inválido.                                                                                             |
| 404  | Concurso no encontrado.                                                                                                             |

---

## Resultado exitoso

### HTTP 200

```json
{
  "mensaje": "Te has inscrito al concurso exitosamente.",
  "codConcurso": "upds-001"
}
```

---

## Resumen funcional

La UJ-12 permite que un usuario se inscriba a un concurso, validando primero que el concurso exista, que no sea el creador, que no esté en curso y que, en caso de ser privado, la contraseña ingresada sea correcta. Si el usuario ya había participado, el sistema evita duplicar registros y puede reactivar su inscripción.
