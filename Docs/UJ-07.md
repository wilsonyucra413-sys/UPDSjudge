# UJ-07 - Gestión de roles de usuarios

## Descripción

Como **Administrador de Roles**, quiero asignar o revocar los roles **Administrador de Concursos** y **Administrador de Roles** a otros usuarios para delegar la administración del sistema.

Esta funcionalidad permite consultar los roles disponibles, buscar usuarios y administrar los permisos asignados a cada uno.

---

# Endpoint base

**Ruta:** `/api/Roles`

### Acceso

Esta funcionalidad solo puede ser utilizada por usuarios que posean el rol:

```text
AdministradorRoles
```

---

# Funcionalidades incluidas

## 1. Listar roles disponibles

### Endpoint

**GET** `/api/Roles`

### Descripción

Obtiene la lista de todos los roles registrados en el sistema.

### Respuesta exitosa

```json
[
  {
    "idRol": 1,
    "nombre": "AdministradorRoles"
  },
  {
    "idRol": 2,
    "nombre": "AdministradorConcursos"
  },
  {
    "idRol": 3,
    "nombre": "Usuario"
  }
]
```

---

## 2. Buscar usuarios

### Endpoint

**GET** `/api/Roles/usuarios`

### Parámetros

| Parámetro    | Tipo   | Descripción                       |
| ------------ | ------ | --------------------------------- |
| query        | string | Búsqueda por nombre o correo.     |
| pagina       | int    | Página a consultar.               |
| tamanoPagina | int    | Cantidad de registros por página. |

---

## Validaciones realizadas

### Validación de paginación

Si:

* `pagina < 1`

Se utiliza:

```text
1
```

Si:

* `tamanoPagina < 1`
* `tamanoPagina > 50`

Se utiliza:

```text
10
```

---

### Exclusión del superusuario

El usuario con **ID = 1** corresponde al **superusuario** del sistema.

Este usuario posee los **tres roles principales**:

* Usuario
* AdministradorConcursos
* AdministradorRoles

Por motivos de seguridad:

* no aparece en la búsqueda de usuarios
* no puede modificarse
* no puede recibir nuevos roles
* no pueden revocarse sus roles

---

### Respuesta exitosa

```json
{
  "total": 2,
  "pagina": 1,
  "tamanoPagina": 10,
  "usuarios": [
    {
      "idUsuario": 5,
      "nombre": "Juan Pérez",
      "correo": "juan@gmail.com",
      "estado": "Activo",
      "roles": [
        "AdministradorConcursos"
      ]
    }
  ]
}
```

# 3. Asignar un rol

### Endpoint

**POST** `/api/Roles/agregar`

### Ejemplo de solicitud

```json
{
  "correo": "usuario@gmail.com",
  "idRol": 2
}
```

---

## Validaciones realizadas

### 1. Correo obligatorio

Debe enviarse el correo del usuario.

**Si no se envía:**

```json
{
  "mensaje": "El correo es obligatorio."
}
```

---

### 2. Existencia del usuario

Debe existir un usuario registrado con ese correo.

**Si no existe:**

```json
{
  "mensaje": "No existe un usuario con ese correo."
}
```

---

### 3. Estado del usuario

Solo se pueden modificar usuarios activos.

**Si está inactivo:**

```json
{
  "mensaje": "El usuario está inactivo, no se pueden modificar sus roles."
}
```

---

### 4. Existencia del rol

El rol indicado debe existir.

**Si no existe:**

```json
{
  "mensaje": "El rol especificado no existe."
}
```

---

### 5. Protección del superusuario

El usuario con **ID = 1** no puede ser modificado.

**Si se intenta modificar:**

```json
{
  "mensaje": "No se pueden modificar los roles del usuario administrador por defecto."
}
```

---

### 6. Rol duplicado

No se puede asignar un rol que el usuario ya posee.

**Si ya tiene el rol:**

```json
{
  "mensaje": "El usuario ya tiene el rol 'AdministradorConcursos'."
}
```

---

### Respuesta exitosa

```json
{
  "mensaje": "Rol 'AdministradorConcursos' asignado correctamente a usuario@gmail.com."
}
```

---

# Reglas de negocio

* Solo los usuarios con el rol **AdministradorRoles** pueden administrar roles.
* Los roles disponibles pueden consultarse mediante el endpoint correspondiente.
* La búsqueda de usuarios admite filtros por nombre o correo.
* La búsqueda de usuarios utiliza paginación.
* Solo pueden modificarse usuarios con estado **Activo**.
* El usuario con **ID = 1** corresponde al **superusuario** del sistema.
* El superusuario posee los tres roles del sistema:

  * Usuario
  * AdministradorConcursos
  * AdministradorRoles
* El superusuario no aparece en la búsqueda de usuarios.
* No es posible asignar ni revocar roles al superusuario.
* No es posible asignar un rol que el usuario ya posee.
* No es posible eliminar un rol que el usuario no tiene.

---

# Resumen funcional

La UJ-07 permite administrar los roles de los usuarios del sistema, consultando los roles disponibles, buscando usuarios y asignando o revocando los permisos de **Administrador de Concursos** y **Administrador de Roles**. Además, protege al **superusuario** (ID = 1), evitando cualquier modificación sobre sus permisos para garantizar la integridad de la administración del sistema.
